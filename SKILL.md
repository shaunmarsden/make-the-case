# Make the Case

You do not need to install anything to try this once: copy this whole file, paste it as your first message in any AI chat tool, then follow it with your actual inputs.

Turn real evidence into a case a decision-maker can act on without having been in the room. A case that could apply to any request unchanged has failed at its one job.

## Gather the Inputs

List the material supplied before drafting or auditing anything:

- Notes, conversations, or data that established the actual need
- An existing draft to audit, if one exists
- Confirmed specifics already established (a figure, a date, a name)
- Anything relevant already known about the reader or the group deciding

If a required input is missing, say so rather than filling the gap with a plausible guess.

## Classify the Evidence

- `confirmed`: a detail directly stated or established in the source material
- `inference`: a reasonable interpretation, still worth checking
- `unknown`: a detail needed for the case that was not established anywhere

An `unknown` needs a placeholder held open for confirmation, clearly marked as such. It should never be answered with an inference dressed up as fact.

## Build or Audit the Document

- **Structure**: prose that reads as an argument start to finish, not a reference grid with no narrative. A compact summary above the case is a valid addition, not a replacement for the argument itself.
- **Title**: personalised to the actual situation and reader, not a generic heading.
- **Reader and voice**: work out who actually reads this. If it is someone who was not in the original conversations, write in the third person about the situation, not as though addressing someone who was there.
- **Grounded examples**: each one names a specific fact, its actual cost or impact, and what changes as a result, drawn entirely from the real evidence gathered. An example that would read the same in a different case is too generic; go back to the source material.
- **Cost or resource section**: real figures already confirmed, with an unknown left as an open placeholder rather than an invented estimate.
- **Risk or limitations section**: always present, worded to match what has actually been confirmed, not a boilerplate line that happens to contradict it.
- **Next steps section**: present, and honest about what happens next. Never imply that sending the document finishes the process.

## Apply the Guardrails

- Never invent a figure, quote, date, or commitment that was not established by the sources
- Never let a confirmed detail already in hand get replaced by a generic placeholder
- Never let the risk section contradict something specific already established
- Keep every example grounded in the real evidence; if it would read the same in an unrelated case, it is doing no work

## Stop When the Task Is Unsafe

Do not produce a finished case when:

- No real evidence is available, and nothing has been established to draw from
- The confirmed detail is too thin to make the examples meaningfully specific
- The request is to remove or soften the risk section rather than correct it

Explain the limitation and ask for the minimum missing detail instead.

## Require Human Review

Before this goes to the decision-maker, check that every figure is one you are actually prepared to stand behind, that the risk section is accurate, and that nothing reads as a guarantee of an outcome. Sending the document stays your own decision.
